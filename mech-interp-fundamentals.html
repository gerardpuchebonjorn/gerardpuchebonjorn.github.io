Basic fundamentals for mechanistic interpretability

In recent years deep learning has become exceedingly good at predicting several types of data from training with huge amounts of data and clever post-training. The best example of it is of course text, with LLMs, but there are others, such as convolutional neural networks for computer vision or the transformer architecture for protein structure prediction.

One of the main reasons these models have become so good is scale: we enable them to have billions or even trillions of parameters, so that there is space to learn as many patterns as possible. There’s a trade-off though, we stop knowing how exactly the model is producing its outcome. I mean, we know about every single matrix multiplication and activation function, but we don’t understand the decision-making process. Trying to do so is what mechanistic interpretability attempts.

fundamentals

First let’s see an example where we can clearly see the decision-making process in a machine learning model. The best example I can think of is decision trees. Consider this old typical model to classify potential breast-cancer tumors as benign or malignant. We get the following dataset:

Then, we can train a decision tree classifier. The main idea is: look at every feature and every possible threshold, and pick the single yes/no question (“is worst radius ≤ 16.80?”) that best separates the malignant tumors from the benign ones. “Best” just means that after the split, each side is as close as possible to being all malignant or all benign. We split the data by that question, and then do the same thing again inside each half, until the groups are pure or we hit a maximum depth. Here I kept 426 tumors for training and 143 for testing, with a maximum depth of 2.

So we can clearly see how the model is deciding to classify the tumor as benign or malignant, you can literally see the chain of decisions for any input. If the worst radius is ≤ 16.80 and the worst concave points are ≤ 0.14, it is benign. If the worst radius is ≤ 16.80 but the worst concave points are above 0.14, it is malignant. If the worst radius is above 16.80, it is malignant, unless the texture error is ≤ 0.47, in which case it is benign.

Now let’s look at a convolutional neural network to classify images. For instance, we can refer to the architecture of AlexNet, which looks mostly like:

We don’t need to get into the exact details of the architecture. The idea is that a filter is just a small grid of numbers, say 3×3, that slides over the image. At each position it multiplies its numbers with the pixels underneath and adds everything up:

output = w₁·x₁ + w₂·x₂ + … + w₉·x₉ + b

If the patch of pixels looks like the pattern stored in the filter, this number is big; if not, it is small. Then a simple function, ReLU(z) = max(0, z), keeps the positive values and sets the rest to zero, so we get a map of where in the image the pattern appears. For example, a filter with negative numbers on its left column and positive ones on its right lights up on vertical edges.

Stacking layers builds on this: the first layers find edges and colors, the next ones combine those into textures, then into parts like eyes or wheels, and the last ones into whole objects. At the end, the fully connected layers turn everything into one score per class. None of these numbers are chosen by hand, they are all learned, about 62 million of them.

But we can clearly see that we no longer identify precisely the decision-making behind each prediction: there is no single readable rule like “worst radius ≤ 16.80”, just millions of numbers that together happen to work.
