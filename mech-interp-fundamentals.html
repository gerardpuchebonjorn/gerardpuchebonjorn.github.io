Basic fundamentals for mechanistic interpretability

In recent years deep learning has become exceedingly good at predicting several types of data from training with huge amounts of data and clever post-training. The best example of it is of course text, with LLMs, but there are others, such as convolutional neural networks for computer vision or the transformer architecture for protein structure prediction.

One of the main reasons these models have become so good is scale: we enable them to have billions or even trillions of parameters, so that there is space to learn as many patterns as possible. There’s a trade-off though, we stop knowing how exactly the model is producing its outcome. I mean, we know about every single matrix multiplication and activation function, but we don’t understand the decision-making process. Trying to do so is what mechanistic interpretability attempts.

fundamentals

First let’s see an example where we can clearly see the decision-making process in a machine learning model. The best example I can think of is decision trees. Consider this old typical model to classify potential breast-cancer tumors as benign or malignant. We get the following dataset:

Then, we can train a decision tree classifier. The main idea is: look at every feature and every possible threshold, and pick the single yes/no question (“is worst radius ≤ 16.80?”) that best separates the malignant tumors from the benign ones. “Best” just means that after the split, each side is as close as possible to being all malignant or all benign. We split the data by that question, and then do the same thing again inside each half, until the groups are pure or we hit a maximum depth. If the worst radius is ≤ 16.80 and the worst concave points are ≤ 0.14, it is benign. If the worst radius is ≤ 16.80 but the worst concave points are above 0.14, it is malignant. If the worst radius is above 16.80, it is malignant, unless the texture error is ≤ 0.47, in which case it is benign.

Now let us look at another model, an LLM, we can use gemma-2-2b as an example. What happens when the model receives the text below and has to predict the next word (token)?

The actual truthfulness of the justice system in the US is _

Its whole job is to guess what comes in place of the _.

In order to understand this we shall go through a bit of a breakdown of the architecture.

From far away, the model is simple. The text is turned into a list of vectors, one per piece of text. Those vectors then go through 26 layers, and every layer is the same two blocks: an attention block and an MLP. At the end, the vector of the last position is turned into a probability for every possible next token. In total that’s about 2.6 billion learned numbers. Let’s break it down.

from words to tokens

First, the words become tokens: whole words, pieces of words or punctuation, are turned into an ID (see LLMs breakdown for a proper explanation on this). Each token is just a number.

But the model can’t do much with a single number, so it swaps each ID for a list of 2,304 numbers. Picture a huge table with one row per token, 256,000 rows; the ID just says which row to grab. Those numbers start out random and get adjusted during training, so words that are used in similar ways end up with similar lists (“king” and “queen” end up close). This list, the token’s vector, is what the model actually works with.

That vector is where the token lives from now on. Think of it as a running notepad, called the residual stream: each block reads it and then adds its result back on top, instead of replacing it:

x ← x + Attention(norm(x))
x ← x + MLP(norm(x))

The “norm” is RMSNorm: it divides the vector by its typical size, √(mean of x²), so the numbers stay at a sensible scale as more and more gets added over 26 layers.

The attention block is the only place where tokens talk to each other. On its own, the vector for “is” knows nothing about “justice” or “US”. In attention, every token builds a query (what am I looking for?), and every earlier token offers a key (what do I contain?) and a value (what I’ll pass on). The match between a query and a key is a dot product, q·k; softmax turns these scores into weights that add up to 1, and the token receives the weighted sum of the values. A token can only look backwards, never at future words. Gemma-2-2b does this with 8 heads in parallel per layer, each free to look for something different.

The MLP then works on each token on its own, with no mixing between positions. It multiplies the 2,304 numbers by a matrix to get 9,216 numbers, passes them through a nonlinearity (GELU, which roughly sets negatives to zero), and multiplies back down to 2,304. You can picture the 9,216 middle values as “neurons” that each fire for some pattern; this is where much of what the model knows seems to be stored. (Gemma actually uses a gated version, with two up-matrices multiplied together, but the idea is the same.)

After the 26th layer, we take the vector at the last position (“is”), normalize it one last time, and compare it with every row of the embedding table with a dot product. That gives 256,000 scores, the logits, one per token. Softmax turns them into probabilities: pi = ezi / Σj ezj. For our prompt, the model’s favourite is “a” with 13%, then “being” (5.5%) and “not” (4.3%). Finally we sample: pick one token at random following those probabilities (or just the top one), append it to the text, and run the whole thing again for the next token.

So everything the model “thinks” about our sentence has to pass through those 2,304 numbers per token, layer after layer. From this we will see that, for example, we can stop at any layer and look at what is in the residual stream there.
