notes on programming courses

programming courses are a bit of a topic nowadays, since learning to code just for the ability to translate natural language into machine language is close to useless: LLMs do it far better. even so, I do not think they are meaningless. in fact, knowing that we don’t need to worry about memorising plt.scatter, or the different syntax of assembly, C or python, you can focus on the nice parts of it.

thinking computationally

the first good thing is learning to think in programming terms: going from pure maths to “how should we structure this to do it on a computer?”. an easy example is implementing matrix multiplication yourself, first with the obvious three for loops:

for i in range(n):
    for j in range(n):
        for k in range(n):
            C[i][j] += A[i][k] * B[k][j]

then you start asking questions. this does n3 multiplications; can we do fewer? (yes: strassen gets it to about n2.81, and nobody knows how low it can go.) does the order of the loops matter? (on a real machine, a lot, because of how memory is laid out.) the maths is the same in every version, but the computation is not, and seeing that difference is the whole point.

data structures and algorithms

data structures and algorithms is an amazing topic now that we can leave the implementation to LLMs. deciding between a linked list, an array or a hashmap is not about syntax, it is about understanding what each one is good at and what it costs. that decision is still yours.

and especially complexity: analysing how the cost of an algorithm grows with the input is a truly fascinating topic (I think complexity theory is quite amazing to study). why does binary search take log n steps? why can’t a comparison sort beat n log n? why is P vs NP such a big deal? these are maths questions disguised as programming questions, and they are some of the most beautiful ones.

learn the maths behind it all: why it works, why it is correct, why it is fast. the implementation you can always ask for; the understanding you cannot.

on AI

the same rule as for maths applies: you should be able to reason about the problem without it. write a few things by hand at the start, mostly to understand what the computer is actually doing. past that, let the LLM write the code and spend your time on the parts that need thinking.
